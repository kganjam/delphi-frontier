# Amendment 1 (registered BEFORE any trained result is seen): qualifications from the independent review, and a separate secondary evaluation

Single-reader, not independently reviewed (the independent review is `messages/rd-diffusion-review-to-root-infra-market-r1.md`, delivered before any training result). The frozen pilot (PREREG.md, rd_ddpm.py `25455430…`, config.json `bc77ebc5…`, packet `76eb4a7b…`) is **unchanged**, will be run unchanged, and its metrics will be reported as they come out. Nothing here tunes on or reacts to held-out output.

## Qualifications that apply to the frozen primary results
1. **"W1" in the frozen outputs (`amp_w1_rel`, `amp_marginal_w1_rel`) is an interpolated midpoint-quantile approximation, not the exact empirical Wasserstein-1.** On the reviewer's software fixture (32 reference amplitudes 1; generated 31 zeros and one 32) the exact value is 1.9375 and the frozen function gives 1.453125 (tested, `tests/test_rd_diffusion_audit.py`). It is reported under the name "interpolated-quantile W1 approximation"; the baselines and null use the identical formula, so comparisons among them stay like-for-like.
2. **Completeness is decided by identities and counts, not by the job's `ok: true`.** `audit_result.py` (fail-closed) checks the 160 conditions x 5 methods, no skipped or failed ensemble run, 4200 training runs and 30,000 steps, 2400/1200 marginal rows, frozen code/config/checkpoint hashes, CUDA, all five files. A run failing the audit is a failed or partial run, not a valid empty result. Training runs the solver flagged `failed` are allowed by the PREREG only if disclosed in the receipts.
3. **Non-finite values**: the frozen `evaluation.json` may contain NaN/Infinity text. They are located, shown as status "nonfinite", and never rendered as numbers or dropped to turn a run green.
4. **`nearest10_pooled` is the deterministic conditional-mean-field baseline** (the summary key is `conditional_mean_of_nearest10`).
5. **Boundary statement corrected**: in the network the stride-one residual convolutions use replicate padding; the two stride-2 down-sampling convolutions (`d1`, `d2`) use **zero** padding. Padding is an architectural choice, not a guarantee that generated fields satisfy the PDE; equation satisfaction is **unknown** and is only measured by the rollout statistic, which is a PDE-flow drift magnitude from a sampled field, not a learned temporal-consistency error or steady-state residual. The source solver's cosine/Neumann convention is exact only inside the solver.
6. **Time conditioning** is over four snapshot times (50, 100, 150, 200 tau) of random-initial-condition runs: the model learns a distribution over seed-induced snapshots, not a temporal integrator, and says nothing about unseen times. DDPM denoising steps are not physical or biological time.
7. **Warm-up** in the frozen timing code uses 64 samples while timed batches are 1024; solver time (1024 runs same device, 64 runs CPU) and DDPM time are different workloads. No speedup is claimed.
8. **Recoverability**: no intermediate checkpoint is saved; the checkpoint contains EMA weights and train-only normalisation (not optimizer or RNG state). A timeout may recover nothing. `evaluation.json` is written only after all evaluation and timing, so a timing failure after a saved checkpoint is a partial failed run. Only a display subset of fields is in `examples.npz`: the full 160-condition generated ensemble is **not** returned by the frozen job.
9. **Evaluation families are not independent**: `test_seed` shares settings with training; `ensemble` shares settings with `test_param`; four snapshots per run are correlated. Solver fidelity is checked against the existing numpy solver at one anchor (the reviewer measured 3.2e-13 at N = 81, tau = 2) and at small CPU/CUDA controls, not convergence over the prior at N = 64, tau = 200.

## Secondary evaluation (registered now; distinct source hashes)
After the frozen job returns, a **separate** run may be admitted by infra with `secondary_eval.py` (sha256 recorded in its output, with `exact_w1.py` and `audit_result.py`): it loads the returned frozen checkpoint (no training, no new weights), calls the frozen `rd_ddpm.evaluate` unchanged with the same seeds, adds the exact empirical W1 for the same quantities, **saves the full generated ensemble** and the solver ensemble, checks whether it reproduces the returned frozen metrics (GPU generation may differ; any difference is reported, not corrected), and writes strict JSON (`allow_nan=False`). Its numbers are labelled SECONDARY, never replace the primary results, and are reported next to them. It tests only a metric definition and retention, not a new model. It was tested on the CPU smoke checkpoint only (a software control, not a result).
