# How the system was built

Companion to the live System page: https://studio.morphoswarm.ai/#/work

## 1. What was built

A public node with five surfaces, all served from one deployment:

| Surface | What it is |
|---|---|
| **Studio** | The flying-fish project across eleven biological scales, each panel holding sources, models, equations, media and an explicit gap |
| **Frontier** | Open questions as records: field questions, project gaps and questions generated by the design work |
| **Knowledge** | 21 seeded claims with conditions and review status, a graph view, and semantic search over 2,444 embedded documents |
| **Evidence** | Sources, disagreements, replayable results and artifacts with hashes |
| **System** | The build itself: specs, owner board, receipts, resources, and what remains unknown |

Plus two machine surfaces: a REST API and an **MCP endpoint** at
`https://studio.morphoswarm.ai/mcp` exposing 21 tools (18 read, 3 opt-in write).

## 2. Architecture

- **Store.** PostgreSQL 16 with pgvector, on its own instance and port, separate from any
  earlier project database. Nine record types (SPEC-001) with explicit field contracts.
  Every record carries a namespace, kind, id and a **content-addressed version**, so a
  reference pins exact bytes.
- **Review is separate from the record.** There is deliberately **no accept tool**.
  Proposing returns `proposed`, never `accepted`. An upstream label is an assertion by
  that upstream, never local acceptance (SPEC-002).
- **Web application.** Vanilla JavaScript, no bundler and no npm build step. Two vendored
  libraries, each with its licence: KaTeX for equations, three.js for the GLB viewer. The
  only build step is a data snapshot: a script reads tracked repository files, records a
  sha256 for every input, and copies a video or mesh into the published tree **only when
  its bytes match the declared digest**. The current snapshot hashes 848 input files.
- **Snapshot or live.** The page asks `/api/health`. If the node answers, records, search,
  questions and the solvers read the running node. If it does not, the page falls back to
  the committed snapshot and **says so in a banner**. An interface the node does not serve
  raises `Unavailable` and the UI shows no result rather than a plausible one.
- **Formal layer.** Lean 4.35.0 with a pinned Mathlib revision; five proof families with
  receipts. See [05-lean-for-biology.md](05-lean-for-biology.md).
- **Coupling layer.** Typed ports between models, with three verdicts and a bias toward
  refusal. See [06-simulations-across-scales.md](06-simulations-across-scales.md).
- **Releases.** The service runs from `app -> releases/<40-hex commit sha>`, an immutable
  `git archive` of exactly that commit plus a build-info receipt. Only committed content is
  ever archived, so a working tree cannot leak into a release. Deploys swap the symlink
  atomically, restart, health-check three times in a row, and roll back automatically on
  any failure. The predecessor release stays on disk and stays addressable.

## 3. How the work was organised

Work was carried out by many AI sessions (several harnesses and models) plus people, with
a coordinating session allocating deliverables. The owner board in the repository lists
**24 deliverables** at P0/P1/P2 with a named owner and a next acceptance for each. Owners
recorded in that board include: `codex-03` (site and database), `claude-02`, `dx-submit`
(vector index), `dx-corpus` (citations and lineage), `dx-critic-r1` (independent browser
critique), `dx-market-r1` (autoformalization), `claude-04`, `claude-05` (print forms,
scale formation), `claude-06`, `claude-11` (genomic/tissue/cell data, lifecycle),
`claude-12` + GPU ops (foundation-model assays), `claude-15` (prior-art differentiation),
a guilds group, and several native workers (bioelectric, mechanobio, resource scaling).

**Honest limit on that list.** All of these share one git identity, so authorship cannot
be derived from the commit log. A correction in our own ledger moved the headline
contributor count from 4 to a floor of 11, and stopped describing 31 as *active*; that
floor rests partly on the coordinating session's attestation of which harness produced
which artifact, not on independent authorship evidence. We report it as a floor.

## 5. What is finished and what is not

The repository's own goal checklist stands at **18 of 34 items done**. Open items include:
the SPEC-017 self-validation loop; a survey of Xenobot/ICDO and further multiscale
simulators; a complete Playwright critique of every route; equations and parameters shown
for *every* implemented subsystem; regional assurance from actual checks; a sourced
developmental/lifecycle slice; source-backed genetic implementation blueprints; bounded
inverse design with held-out robustness checks; and an off-host backup.

**SPEC-005's own acceptance list has 11 items and none is checked off.** Several of the
underlying capabilities exist and are demonstrable, but the end-to-end acceptance each
item demands has not been recorded, so they stay unchecked. We would rather show an
unchecked box than a checked one we cannot evidence.

## 6. The two levels of claim, kept apart

Every statement on the System page is tagged as one of:

- **author report** — what the repository's own documents say: checkboxes, status text,
  owners, plans. Written by the people or agents doing the work.
- **measured** — what a receipt in this tree records: a run with its hash and result. **A
  receipt covers only what it says it covers.**

This distinction is enforced in the page code, not just the prose.
